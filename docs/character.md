# 圆球小飞猫

## 角色设定

一键游戏里，玩家第一眼要读出“披着红斗篷、向右飞的猫”。所以主角不追求写实，而是一个抽象的圆球猫：头和身体是同一个圆。

- **造型**：
  - 圆球半径 17 个世界单位，碰撞圆（半径 13）正好在里面，四周留出约 4 个单位的宽恕，画出来的圆基本就是碰撞判定。
  - 顶上两只圆角三角耳，带粉色内耳。
  - 豆豆眼带两粒高光，看向前方；奶油色口鼻、粉鼻子、ω 小嘴、腮红；额头三道虎斑纹，奶油色肚皮。
  - 四只小圆爪；一条 S 形卷尾巴，带两道环纹。
  - 燕尾红披风：上沿一道亮边，下沿露出暗色里子。
- **画风**：平涂加场景统一的深紫墨色描边（`#2a1b3d`，2.5 个世界单位，和障碍物一样）。耳朵和圆球共用一条合并的外轮廓；后背下方一道月牙形暗面表现圆润感；不用渐变。
- **色板**：
  - 毛色：`#f29a38`，暗面 `#d36f22`，和界面主题的橙色一致。
  - 奶油色：`#fff4e0`，和界面的奶油色一致。
  - 粉色：`#f58c95`。
  - 披风：`#e0393f`，里子 `#a61f3b`，亮边 `#ff7a63`。
  - 小鱼干：金色 `#ffd256`。
- **为什么是圆球**：
  - 全部由圆、圆角三角和曲线组成，旋转、挤压、拉伸都不会走形。
  - 和圆形碰撞判定一致，玩家不会觉得判定不公平。
  - 和矢量场景、界面是同一种画风。

## 姿态与动画

所有动作都是连续参数驱动，没有固定帧之间的跳变：

| 状态 | 画面 |
| --- | --- |
| 巡航 | 开始页轻轻上下浮动；披风迎风波动，尾巴摆动，偶尔眨眼 |
| 点一下 | 猛地抬头，圆球沿冲劲拉长；前爪向前伸，一道更大的波浪沿披风传到下摆 |
| 下落 | 慢慢低头俯冲，爪子放下，披风被气流扬起；下落很快时睁大眼、张嘴 |
| 撞到天花板 | 压扁、眯眼（> <）、耳朵一缩 |
| 按住滑翔 | 披风像翅膀一样张开，抖得更快；前爪一直向前伸 |
| 叼到小鱼干 | 张嘴 0.2 秒 |
| 撞到啦 | 下落途中滚成翻肚皮（×× 眼、吐舌、耳朵贴平、爪子朝天），落地压扁一下，尾巴还在抽动 |

暂停冻结所有动作，重开恢复姿态。减少动态效果模式下没有挤压拉伸、披风不波动、坠毁直接翻肚皮。

## 实现

- **绘制**：在 [`src/render/cat.ts`](../src/render/cat.ts)。`paintCat(ctx, pose, colors)` 用普通 Canvas 2D 路径，在原点按世界单位、朝右画整只猫。绘制顺序：披风 → 尾巴 → 远侧爪子 → 耳朵和圆球（合并外轮廓）→ 暗面、肚皮、虎斑 → 脸 → 近侧爪子。
- **动作驱动**：在 [`src/render/animator.ts`](../src/render/animator.ts)，把模拟状态转成姿态参数，只读不写。
- **披风**：
  - 中线分 8 段采样，宽度从领口到下摆平滑变宽。
  - 一道沿长度传播的正弦波，越到下摆越大。
  - 下摆有燕尾缺口。
  - 滑翔时长度、宽度和角度连续过渡到张开的形状。
- **轮廓**：耳朵和圆球合成一条外轮廓：沿圆周走，遇到耳朵就绕出去再回来。耳朵折平时也成立，头里不会多出耳根的线。
- **直接绘制**：所有猫都直接画进场景画布，帧循环里不创建画布、不读像素。曾试过先画进离屏画布再贴上，好让幽灵的透明度只应用一次，但每只幽灵每帧多花 0.7ms（Chromium），在无头 WebKit 里更高达约 6ms，所以放弃了。
- **幽灵猫**：同一套几何画成好友毛色的一个平涂半透明剪影，只保留深色的眼睛和嘴（色表按明度映射：黑、银、白、蓝灰、棕）。披风、尾巴、远侧爪子裁在圆球外面，不会透过身体露出来；没有描边和层层细节，任何位置最多是爪子、尾巴、披风三层交叉，不会变成不透明。
- **小鱼干**：矢量绘制。计数牌的图标在加载时由同一段绘制代码生成图片。
- **图标与配图**：`npm run art-assets` 把 `paintCat` 自己的绘制调用录制成 SVG 路径，所以 `public/icon.svg` 是真正的矢量，不会和游戏里的猫走样。再由它生成 180 和 512 像素的 PNG 图标，并导出 `docs/character.png`、`docs/preview.png`、`docs/maps.png`。
- **预览**：开发服务器的 `/tools/gallery.html` 用正式绘制代码展示各个姿态。加 `?sky=22` 看夜景，加 `?debug` 看碰撞圆。

## 验收标准

1. **造型**：在手机实际尺寸和放大预览中，脸、耳朵、披风、尾巴、爪子都清楚；能读出向右飞；四张地图的背景上都清楚。
2. **绘制**：每个飞行姿态（含最大倾角、拉伸、压扁）都完整盖住碰撞圆；幽灵不超出玩家的轮廓、身体盖满碰撞圆、纯毛色处正好一半透明、任何位置都不会不透明；任何翻滚角度都画得完整、不碰画布边。
3. **流程**：起飞、爬升、下落、滑翔、吃小鱼干、撞天花板、坠毁、重开、暂停、五只幽灵同屏都正确；图标、角色预览和游戏截图都从游戏绘制结果导出。

## 本轮验收记录（2026-10-05，矢量圆球猫）

本轮之前有过两版像素猫：先是运行时逐层旋转像素图层，后来改成逐帧手绘。按要求改为矢量后，主角和场景、界面是同一种画风。

- **单测与构建**：192 项单测通过，类型检查和生产构建通过，JS 约 33.4 KB（gzip）。角色相关的单测覆盖暂停冻结、坠毁后重置、点击时拉长抬头、快速下落的表情、撞天花板眯眼压扁、滑翔张开披风并前伸双爪、叼小鱼干张嘴、减少动态效果、动画不改模拟状态，以及幽灵毛色映射。
- **浏览器测试**：四种浏览器配置共 93 项通过、31 项按配置跳过，没有失败项；最后一处改动之后又单独重跑了美术专项（8 项通过）。美术专项抽样 27 种姿态：
  - 最大倾角、拉伸和压扁，张开的披风，爪子前伸和放下，各种表情，各配 3 个披风相位；
  - 翻滚一整圈的 8 个角度，以及落地压扁。

  检查项：碰撞圆完整藏在实心造型里；猫不碰画布边；幽灵不超出玩家轮廓；幽灵身体盖满碰撞圆；纯毛色处正好一半透明；任何位置不超过 87.5%（爪子、尾巴、披风三层交叉处）。
- **测试暴露的问题**：
  - 耳朵完全折平时，外轮廓会丢掉耳朵（只剩粉色内耳），已修复。
  - WebKit 读取像素后会换一套光栅化器，导致"暂停时画面不变"的比较出现抗锯齿差异。测试现在一开始就要求便于读取的画布，相同的帧得到相同的像素。
- **实机画面**（无头 Chromium，390×844 手机尺寸）：
  - 自动驾驶连续截帧：巡航、点击拉长、上升、下落、俯冲之间切换顺滑；
  - 按住空格看滑翔披风和能量圆环；
  - 坠毁看翻滚、翻肚皮落地和眩晕星星。
  - 能量圆环移到耳朵上方（−38），得分飘字起点移到 −36，不再一出现就盖住脸。
  - 这不是真机检查。
- **性能**（生产预览，五只幽灵同屏）：
  - 花园、书房、云端在桌面 1280×800 和手机配置 390×844 各采样 60 秒，每一帧都画了五只幽灵；每帧 JS 耗时中位数 0.5–0.6ms，p99 1.8–2.0ms。
  - 帧率 55.5–59.6fps。测量时机器上有别的负载，同样条件下：已提交的上一版是 57.6–58.0fps，新角色不带幽灵是 57.7–57.9fps，说明没有退步。
  - 这不是手机真机测量。
